# Image Canvas (raylib)

最简单的 raylib 图片画布示例。

## 功能

- 素材与桌面物件分离：物件持有素材 ID 数组，渲染和命中使用物件当前显示素材下标
- 拖入图片 = 添加素材，并创建引用该素材的物件；拖入 `.dsk` 或 `dsk` 文件夹 = 增量合并到当前场景
- `文件 → 导入` 选择图片时只添加素材、不创建物件，成功后自动打开素材管理窗口并选中新素材
- 顶栏直接点击 `素材` 打开素材管理窗口：缩略图、名称、重命名、更换、删除
- 顶栏直接点击 `物件` 打开物件管理窗口：新建、管理（重命名 / 素材 / 占用锁）、删除
- 顶栏 `联机` 菜单提供 `连接` 和 `开放`：连接打开远程连接对话框，开放显示本地服务地址和端口
- 顶栏直接点击 `脚本` 打开脚本窗口，self 默认填入 `self`（以当前用户身份执行）
- 每个物件有层数（int）和时间戳；渲染时按层数和时间戳排序
- 新建的物件没有素材，不渲染也无法点选/拖动，直到加入素材
- 左键点击物件即选中并占用，按住拖动移动物件；只有 alpha == 255 的像素可以命中
- 画布上右键物件打开上下文菜单：菜单项 / 查看 / 脚本 / 删除；右键空白处打开 global 菜单
- global 菜单为空时仍固定显示 `回到原点` / `缩放` / `背景` / `脚本` 四项；只有存在脚本菜单项时才在菜单项和固定动作之间画分隔线
- 被选中的物件周围显示阴影 shader；阴影轮廓只由 alpha == 255 的像素生成
- 素材管理、物件管理和物件素材弹窗中，点击未使用的空白区域会取消当前选择
- 左键拖动空白处，平移视角
- 滚轮以鼠标位置为中心缩放视角，缩放范围限制为 20%–500%
- `右键空白 → 回到原点` 把世界原点对齐到窗口中心（保留当前缩放）
- `右键空白 → 缩放` 子菜单可切换 100% / 200% / 50%
- `右键空白 → 背景` 子菜单可切换纯白 / 格点 / 格纹 / 棋盘背景
- 导入失败、拖入失败、素材/物件操作失败、连接失败等会在顶部显示自动消失的提示条
- 窗口可自由缩放；使用垂直同步，帧率跟随显示器刷新率，不锁 60 帧
- 支持无头服务器 + 远程客户端联机同步场景
- 每个用户最多占用一个物件；占用期间其他用户不能操作，物件会高亮，右下角显示占用者用户名
- 桌面显示其他在线用户的光标位置，使用该用户的颜色绘制圆点和右下角小号用户名
- 指定 `--save 文件` 时，服务端每 30 秒以及正常退出时保存到该文件；未指定时完全不写磁盘
- 单机/作为 host 的窗口显示 `文件` 菜单：`导入` 按文件类型处理，`导入文件夹` 直接导入 `dsk` 目录，`导出` 把当前场景写入选择的 `.dsk`

## 存档

只有显式提供 `--save 文件` 时服务端才会存档：每 30 秒以及正常退出时，把当前内容原子写入
该文件。写入先落到同目录唯一临时文件，`fsync` 后由 libuv 原子替换，避免中途失败留下半个存档。没有 `--save` 时服务端不写任何存档文件；只给 `--load` 时是只读导入。

普通本地模式启动时不会自动导入；命令行 `--load 文件或目录` 会在启动时加载存档。
`文件 → 导入`、`文件 → 导入文件夹` 和拖入 `.dsk` 或文件夹则是**增量导入**：不打开新窗口，直接把文件或目录中的全局环境、素材、
物件（含物件环境）和菜单合并进当前场景。素材、物件或全局变量重名时保留现有内容，跳过冲突项，
并在 host 窗口通过提示条显示冲突；无头服务端直接打印到 stderr。

存档沿用联机全量同步的场景范围，但联机快照使用 ID 且不包含脚本环境和菜单函数；存档把引用
全部换成名称字符串，并额外保存环境与菜单函数。

存档是 ZIP 压缩包，只是把扩展名改成 `.dsk`；解压后结构如下：

```text
dsk/
  assets/
    素材文件.png
    ...
  objects/
    物件名称.json      # 也支持 物件名称.hjson
    ...
  scene.json          # 可选；也支持 scene.hjson
```

导入时既接受直接包含 `assets/`、`objects/` 的压缩包，也接受整个 `dsk/` 目录作为压缩包根节点。
`文件 → 导入文件夹`、拖入文件夹和 `--load 目录` 也会直接读取同样的目录结构，不需要先压缩。
素材名称自动取文件名去掉最后一个扩展名；扩展名保留用于加载图片。物件名称取
`objects/<名称>.json` 或 `objects/<名称>.hjson` 去掉后缀后的部分。

物件 JSON/HJSON 可以只写需要的字段。`.json` 文件允许直接使用 HJSON 语法，也支持命名为 `.hjson`：

```json
{"assets": ["name1", "name2"], "env": {"x": 1, "y": "str"}}
```

- `assets`：按顺序引用素材名称（不含扩展名），默认空
- `env`：物件局部脚本环境，默认空对象
- `x`、`y`：位置，默认 `0`
- `layer`：层数，默认 `0`
- `hidden`：基础隐藏状态，默认 `false`
- `assetIndex`：当前素材下标，默认 `0`
- `menu`：菜单数组，默认空；格式为 `[{"name": "菜单名", "func": "函数文本"}]`
- 绘制时间戳不写入存档；导入时按物件处理顺序分配互不相同的值

支持的 HJSON 写法包括：

- `#`、`//`、`/* ... */` 注释
- 不加引号的字段名和单行字符串
- 可省略逗号和尾随逗号
- 根对象可以省略外层括号
- 三引号多行字符串，适合保存脚本函数文本

导出时仍写标准 JSON（`.json`）。

`scene.json` / `scene.hjson` 可选，用于保存全局内容：

```json
{"version": 1, "env": {}, "menu": [{"name": "名称", "func": "函数文本"}]}
```

所有跨对象引用都保存为名称字符串，不保存素材、物件或用户 ID；光标、占用锁、时间戳、
按用户可见度等瞬态状态不保存。用户环境、用户菜单、用户颜色和 `canscript` 属于在线会话，
不写入磁盘。

Git 跟踪源码、CMakeLists.txt、README、`.gitignore`、`.github/`、`assets/` 和
`third_party/`。以下内容不会提交：

- `image_canvas`、`build/`、`compile_commands.json`

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/client.c` / `src/client.h` | 已连接后的客户端主循环：UI、拖放、锁定 pending、加载动画和渲染 |
| `src/main.c` | 原生入口：参数、窗口、本地服务端、连接和客户端启动 |
| `src/utils.c` / `src/utils.h` | 公共 `u64`、`IdGroup`、`TextBuffer`、`StrDup` 和随机数工具 |
| `src/script.c` / `src/script.h` | 脚本解释器：现场解析、按 self 隔离的环境、函数支持参数并内置 `messagef`/`object`/`user`/`flip`/`size`/`assets`/`typeof`/`menu`/`rand`/`int`/`move`/`pos`/`locked`/`color`/`script`/`fork`/`untouch`/`hide`/`show`；运行时值使用 json-c，原生支持 `u64` |
| `third_party/tinyfiledialogs.c` / `.h` | 跨平台原生文件/文件夹对话框（zlib licence） |
| `src/entity.c` / `src/entity.h` | 哈希表：id → 对象指针，平均 O(1) 查找 |
| `src/menu_array.c` / `src/menu_array.h` | 内部菜单名称/函数数组操作：全局、用户和物件菜单共用同一套增删与替换逻辑 |
| `src/user.c` / `src/user.h` | 在线用户：用户 ID、名称、光标状态和颜色，支持查找、增删和遍历 |
| `src/strmap.c` / `src/strmap.h` | 哈希字符串 → `void *` 索引，惰性构建按名称排序的遍历视图 |
| `src/netutils.h` / `src/netutils.c` | 跨平台传输抽象：native libuv TCP，Web 端保留 TCP 监听 stub |
| `src/net.c` / `src/net.h` | libuv TCP 联机：无头服务器、权威场景、增量操作、物件占用、在线光标和全量快照 |
| `src/assets.c` / `src/assets.h` | 素材库：name → id 有序索引；`Asset` 逐个 malloc 并由 entity 按 id 注册 |
| `src/object.c` / `src/object.h` | 物件：name → id 有序索引；`Object` 逐个 malloc 并由 entity 按 id 注册，持有素材数组、层数、时间戳、位置、命中检测 |
| `src/save.c` / `src/save.h` | 服务端存档与导入：libzip 读写 `.dsk`，libuv 处理路径、目录和原子替换；不保存用户私有数据 |
| `src/hjson.c` / `src/hjson.h` | 内部 HJSON 解析器：兼容标准 JSON，支持注释、无引号字段/字符串、可选逗号、根对象省略括号和多行字符串 |
| `src/view.c` / `src/view.h` | 相机与渲染：缩放、平移、坐标转换、背景图案、按层数/时间戳排序绘制物件、选中阴影 shader |
| `src/ui.c` / `src/ui.h` | UI：字体、菜单栏、连接对话框、文件对话框、素材/物件管理窗口、物件素材弹窗、重命名输入 |

素材和物件通过 `entity.c` 建立 64 位 `id` 到对象指针的映射；`id` 只由服务端统一分配。
联机同步和物件对素材的引用都使用 `id`，名称只用于显示，服务端保证名称唯一。素材默认命名为
`asset`、`asset 2`…，物件默认命名为 `object`、`object 2`…。物件使用 `u64 *assetIds`
保存多个素材 ID，数组下标从 #0 开始。

主循环分别保存 `chosen`（当前选中物件指针）和 `dragged`（鼠标是否处于拖动状态）。
数组扩容只移动指针，不会影响选中的物件指针。内部引用一律使用指针或 id：
`Object.assets[]`、`chosen`、UI 选择结果都是指针。

选中阴影使用自定义 fragment shader 采样纹理 alpha，再叠加多份偏移剪影形成柔和阴影，
因此透明 PNG 只在非透明像素周围产生阴影，不会出现图片矩形边框。
重命名时调用 `AssetRename()` / `ObjectRename()` 更新显示名称，不会影响已有引用：

- 素材重命名后，引用它的物件仍然指向同一块 `Asset`
- 物件重命名后，`chosen` / `dragged` 状态仍然有效

UI 通过 `UiEvent` 把「导入素材」「新建/重命名/删除物件」「添加/移除/排序物件素材」
「重命名/更换/删除素材」「回到原点」「缩放」「背景」等动作交给 `main.c`，不直接操作素材和物件。

## 素材管理

顶栏的 `素材` 按钮直接打开素材管理窗口（没有下拉菜单），每个素材显示缩略图和名称。
素材管理列表按名称升序排列；导入、重命名后会自动重新排序。遍历时 `AssetIds()` 返回按名称排序的 `IdGroup`，UI 再通过 ID 从 entity 取素材指针。

先点击列表中的素材进行选择，选中的行会高亮；窗口底部按钮作用于当前选中的素材：

- **重命名**：弹出输入框，支持键盘输入、退格和回车确认
- **更换**：打开文件对话框，替换该素材的纹理；所有引用该素材的物件会同步更新
- **删除**：发送删除请求；服务器按引用计数判断，若仍有物件引用则拒绝删除并通知客户端，素材管理窗口保持打开
- **导入**：在素材管理窗口内继续导入图片，导入后窗口保持打开
- **确定**：关闭素材管理窗口

未选择素材时，重命名 / 更换 / 删除按钮为禁用状态。

素材名称只用于显示；物件通过素材 ID 引用素材，所以重命名和更换都不会破坏已有物件。
删除后素材 ID 和指针才会失效。删除成功后素材管理窗口继续打开，只清除当前素材选择；删除失败会显示提示。

## 物件管理

顶栏的 `物件` 按钮直接打开物件管理窗口（没有下拉菜单）。每个物件显示缩略图（取当前显示素材；空物件显示「空」）和名称。

先点击列表中的物件进行选择；双击物件行可以直接进入「管理」。窗口底部按钮为：

- **重命名 / 管理 / 浮动 / 删除**（左侧，未选择时禁用）
- **新建 / 确定**（右侧）

其中：

- **新建**：创建一个没有素材的物件，放在当前视图中央，并自动选中它。它不会渲染，也不能被点选或拖动；后续操作时再申请锁
- **重命名**：修改选中物件名称；选中时已经持有该物件锁
- **管理**：进入该物件的管理界面并申请占用锁；双击物件行也可以直接进入
  - 点击选择一项后，可以 **上移 / 下移** 调整数组顺序；移动不会改变当前显示素材下标
  - 双击素材，或选中后点击「使用」，切换物件当前显示的素材
  - **移除** 删除数组中的某一项
  - **添加** 打开素材选择窗口，把已有素材追加到数组末尾
- **删除**：删除选中物件本身，不会删除素材库中的素材

每个物件行会显示名称和「层数 N」。渲染顺序规则：

1. 先绘制层数大的物件（层数大的在下面）
2. 层数相同时，先绘制时间戳靠前的物件（后加入的物件在上面）
3. 修改物件（重命名、增删/排序素材、修改层数等）会更新时间戳，
   所以同层内刚操作过的物件会靠上

## 透明像素规则

点击命中和选中阴影都不使用 alpha 阈值，只认 **a 通道恰好为 255** 的像素：

- 点击透明或半透明像素（例如 alpha=254）不会选中物件
- 阴影 shader 只对 alpha == 255 的像素生成剪影
- 物件使用当前显示素材做点击命中和绘制

素材加载时会保存一份 alpha 数组，替换素材时同步更新。

## 物件右键菜单

在画布上右键物件，会在鼠标位置弹出菜单：

- 先列出该物件菜单中的所有名称；菜单非空时才在名称之后显示分隔线；
- **查看**：打开物件管理窗口，并自动选中、定位到该物件；
- **脚本**：打开脚本窗口，self 填入 `object("物件名")`；
- **删除**：立即删除该物件。

点击菜单名称会发送请求到服务器执行对应的菜单脚本。菜单更新不会中断已经打开的右键菜单。

右键物件时也会把它设为当前选中物件。右键菜单打开期间不会操作画布，点击菜单外会关闭。

右键空白处总会打开 global 菜单：先显示脚本定义的 global 菜单名称，至少存在一项时才画分隔线；之后固定显示 `回到原点`、`缩放`、`背景` 和 `脚本`，即使 global 菜单为空也会显示；`脚本` 打开脚本窗口，self 填入 `0`，作为全局执行。点击菜单名称会由服务端执行对应脚本。

## 背景

默认是纯白背景。`右键空白 → 背景` 是有下一级菜单的项目，子选项为：

- **纯白**：空白白色背景
- **格点**：灰色网格点
- **格纹**：灰色网格线
- **棋盘**：白灰相间的棋盘格

图案绘制在世界坐标中，会跟随相机平移和缩放变化；缩放时会自动调整间距，避免线点过密或过疏。

## 导入图片

顶栏的 `导入` 按钮会直接打开系统文件对话框（Linux 使用 zenity/kdialog，Windows 使用原生对话框）选择一张图片，
图片只会加入素材库，导入成功后会自动打开素材管理窗口，不会直接出现在桌面上。
之后通过 `物件` 新建物件，再在「管理」中加入该素材；或者直接把图片拖进窗口
（会同时创建引用它的物件）。

如果系统没有 `zenity`，也可以直接把图片拖进窗口（这会同时添加素材和物件）。

素材选择窗口或文件对话框打开期间，拖入文件会被忽略。raylib 没有跨平台的“禁止拖入”
窗口开关，所以在事件层处理：弹窗期间收到拖入事件后直接取出并丢弃，不添加素材或物件，
也不留到关闭弹窗后再处理。

如果是在素材选择窗口或文件对话框打开时拖入文件，会从窗口顶部滑出一条提示，
约 3 秒后自动消失，不需要点击确认，也不会打断当前操作。

## 本地模式

直接运行 `./image_canvas` 时，程序会以同一可执行文件启动一个独立的本地服务端进程
（`--server --port`），自动选择一个空闲端口，并以 `local` 用户名作为唯一客户端连入。
素材和物件的创建、修改、锁定等操作与联机模式走完全相同的服务器请求流程。普通启动不会
自动导入存档，也不会写存档；需要继续某个存档时使用 `文件 → 导入` 或 `文件 → 导入文件夹` 做增量合并，或命令行
`--load 文件` 启动时加载。增量导入不打开新窗口，也不会自动保存；需要保存时使用
`文件 → 导出` 或命令行 `--save 文件`。

本地服务端监听所有网卡；点击顶栏 `联机 → 开放` 会显示局域网 IP 和端口，其他设备可用该
地址连接。开放后 `联机` 菜单会从当前窗口消失；远程客户端窗口已连接，也不会显示该菜单。
端口随机，客户端退出时会终止本地服务端进程。

## 联机模式

```bash
# 无头服务器，默认端口 7777
./image_canvas --server

# 指定端口
./image_canvas --server --port 9000
./image_canvas --server 9000

# 只读导入，不保存
./image_canvas --server --load canvas.dsk
./image_canvas --load canvas.dsk

# 导入并保存回文件
./image_canvas --server --load canvas.dsk --save canvas.dsk
./image_canvas --load canvas.dsk --save canvas.dsk

# 只指定保存文件，不导入
./image_canvas --save canvas.dsk

# 远程客户端：IP 端口 用户名
./image_canvas 192.168.1.10 7777 alice

# 也可以显式指定用户名
./image_canvas --name alice 192.168.1.10 7777
```

也可以在当前窗口点击 `联机 → 连接`，在弹出的窗口中填写用户名、IP 和端口，确认后
会启动一个新的客户端窗口连接服务器。用户名必填；地址留空时使用 `127.0.0.1`，
端口留空时使用 `7777`；按 Tab 切换输入框，回车确认，Esc 或点击对话框外取消。

同步范围：

- 所有实体 ID 由服务器统一分配；客户端只发送请求，服务器生成 ID 后广播创建事件，请求方也以服务器返回的 ID 为准
- 用户也有独立的 64 位 ID；锁归属、创建请求匹配和“是否自己”判断都使用用户 ID，用户名只用于显示
- 素材：导入时传输一次原始文件字节，之后按 ID 引用；重命名、更换、删除只发送请求，服务器校验并广播后更新本地
- 物件：创建请求由服务器分配 ID；未持锁时，更新和删除只提交目标状态，收到服务器广播后再更新本地
- 物件持锁时，允许先本地修改再提交，因为其他客户端无法操作该物件
- 选中物件时立即申请占用锁；其他用户不能选中或打开该物件的管理界面
- 服务器处理物件的修改、删除时，要求发送者持有对应物件锁
- 退出具体物件管理界面后继续保持选中和占用；切换选择或关闭管理器时释放
- 打开顶栏菜单会取消当前画布物件选择，保证同一用户一次只选中一个物件
- 占用：选中物件时发送占用包，取消选中或关闭管理器时发送释放包；服务器保证同一物件同时只有一个占用者
- 锁定请求会先执行物件的 ontouch；如果回调中调用了 untouch()，untouch 会立即向请求者发送锁定失败包，不再发送重复失败或成功响应
- 物件有锁时，普通脚本调用 untouch() 也会向原持锁客户端发送锁定失败包；客户端据此清除已失效的选择/拖动状态
- 在线状态：服务器保存每个用户的在线状态、光标世界坐标、颜色和 `canscript` 权限，并广播给其他客户端；用户加入时颜色默认为黑色、`canscript` 默认为 true，可分别用脚本 `color(r, g, b)` 和 `script(bool)` 修改
- 脚本 `messagef` 在服务端生成消息：无 `@` 或 `@0` 时广播给所有客户端，`messagef("...")@用户ID` 只发送给指定用户
- 脚本下标：`x#"name"` 使用字符串键，`x#1` 使用整数下标，`x#name` 使用变量 `name` 的值作为键或下标
- 脚本编辑窗口支持方向键、Home/End、Backspace/Delete、鼠标定位光标、Tab/空格缩进；`Ctrl+Enter` 提交
- 脚本最后一行不要求换行符；普通语句、代码块、函数体以及空函数声明都可以直接以 EOF 结束
- 脚本缩进可使用 Tab 或空格；Tab 按 4 列宽度计算，同一行可以混合使用
- 每个缩进块以第一个非空行的缩进为基准；下一非空行缩进小于等于当前行时表示块为空，`if` / `while` / `for` 会报“代码块需要缩进”
- 块内后续行可以继续加深缩进形成嵌套，但回退时必须回到已有缩进层级
- 脚本提交窗口的 self 表达式以提交者身份求值；空表达式按 self=0 执行，非空表达式必须返回整数
- 脚本赋值支持 `=`、`+=`、`-=`、`*=`、`/=`、`%=`，也支持成员目标如 `x#"a" += 1`
- 条件支持 `if` / `elif` / `else`；`elif` 与对应 `if` 同缩进，可连续多个
- 逻辑运算支持 `!`、`&&`、`||`；优先级为 `!` > `&&` > `||`，`&&` / `||` 短路并返回 bool
- 逻辑运算的真值规则：`false`、`null`、`0`、`0.0`、空字符串、空数组、空对象为假，其余为真
- map 可以按向量参与算术：`map + map`、`map - map`、`map * number`、`number * map`、`map / number`、`map % number`
- map 加减要求两边所有字段都是数字且字段集合完全相同；其他 map 运算要求 map 的所有字段都是数字，并只接受右侧/左侧指定的数字标量
- map 运算逐字段计算并返回新 map，不修改原 map；空 map 除法或取模 0 会报错
- 每个物件维护当前显示素材下标；脚本 `flip(x)` 将其切换为第 x 个素材，越界报错
- 函数声明为 `func foo(参数...)`，不支持关键词；所有函数都可以用 `foo(...)@id` 形式指定 self 调用；目标实体没有同名函数时会回退到全局函数
- `@` 只能跟在函数名直接调用的右括号后，函数会按名称在 `@` 目标作用域内查找；`(fn)()@id`、`foo()()@id`、`obj#fn()@id` 都会报错
- 函数值可以作为参数和返回值；返回的函数可以继续调用，例如 `foo()()`、`(fn)()`，但这种调用不能使用 `@`
- 循环支持 `for x in 数组` 和 `for k, v in 对象`
- 数组支持 `arr += value` 追加元素；对象成员赋值 `map#key = value` 会直接创建不存在的字段
- `arr -= n` 删除数组尾部 n 个元素；`map -= key` 删除对象字段（字段不存在时对象保持不变）
- 脚本 `size(x)` 返回对象字段数或数组长度，其他类型报错
- 脚本 `assets()` 返回当前 self 物件的素材 ID 数组；self 不是物件时返回 null
- 只读变量 `type` 表示 self 类型：`"object"`、`"user"`、`"asset"`；self=0 时为 `"global"`
- 只读变量 `caller` 表示当前菜单点击者的用户 ID；global/物件/用户菜单执行时可用，普通脚本执行时为 0
- 特殊变量 `remove` 只能在物件脚本中使用，只能赋值为 bool，初始为 false；任意脚本执行结束后，服务端遍历所有物件，删除 `remove` 为 true 的物件；若物件有锁，先释放锁并发送锁定失败包，再广播物件删除
- 脚本 `typeof(x)` 返回 `"null"`、`"boolean"`、`"integer"`、`"double"`、`"string"`、`"array"` 或 `"object"`
- 脚本 `move({"x": x, "y": y})` 按传入 map 的 `x`/`y` 移动当前 self 物件，忽略其他字段；兼容旧形式 `move(x, y)`；`pos()` 返回 `{"x": x, "y": y}`；`locked(id)` 返回指定物件当前是否被锁定；`color(r, g, b)` 用 0..255 的 RGB 修改当前用户颜色并广播；`script(bool)` 修改当前用户是否允许提交脚本；`hide()` / `show()` 用物件级 bool 隐藏或显示当前 self 物件；`hide(userid)` / `show(userid)` 只设置指定用户的可见度，并进入按用户模式；再次调用零参数版本会丢弃按用户状态并恢复全局 bool。隐藏物件不渲染、不能被画布点选，但仍会出现在物件管理窗口
- 服务器按客户端发送该用户实际生效的 `hidden` bool；按用户可见度是当前服务器会话状态，不写入 `.dsk`
- `fork("name")` 复制当前 self 物件的素材、位置、层、环境、菜单并返回新 ID，重名使用 `name#1` 等后缀
- 物件局部变量 `ontouch` / `ondrag` / `dragged` / `touched` 可直接赋值（不需要先 `var`），只能赋值为 null 或一元函数；`ontouch(userid)` 在玩家锁定物件时调用；`ondrag(userid)` 在物件被拖动期间按客户端同步间隔持续调用，即使鼠标静止也会触发；`dragged(userid)` 在拖动结束时调用；`touched(userid)` 在用户手动释放锁或断开连接时调用
- `touched` 在锁真正清除前执行，此时用户数据和物件环境仍然存在；`untouch()`、服务器拒绝锁定请求、删除物件和 `remove` 清理都不会触发
- 断开连接时服务端先对用户当前持有的物件执行 `touched`，再广播用户离开并清除用户数据
- `untouch()` 立即释放当前 self 物件的锁，不会触发 `touched`
- `canscript` 为 false 时，服务端拒绝该用户的脚本提交；客户端点击脚本按钮或提交脚本时显示红色提示，但菜单脚本和物件事件仍可由服务端执行
- 脚本 `menu("名称", func)` 向 self 对应的物件或用户菜单追加一项；self=0 写入由 entity 管理的 global 菜单；第二个参数传函数值，例如 `menu("问候", greet)`，点击时执行该函数；`menu()` 清空菜单；非用户/物件 self 报错
- 服务端会把菜单名称同步给客户端；客户端不保存 func，菜单只能由服务端脚本修改
- 用户菜单在窗口底部居中显示为按钮，多行时每行居中；服务端只把自己的用户菜单同步给对应客户端
- 服务端拒绝执行其他用户的菜单
- 单次脚本执行有 1,000,000 行执行次数上限，超过后会强制终止并返回错误
- 脚本解释器产生的解析和执行错误会广播给所有在线客户端，以红色提示显示；权限拒绝、菜单不存在等协议层错误仍只发给请求者
- 脚本执行成功且有非 null 返回值时，服务端向调用者发送蓝色提示 `脚本已返回 <JSON>`
- 服务器维护权威场景；新客户端连接时获取一次全量快照
- 服务端与客户端复用同一套 Asset/Object/User/Entity 管理 API；本地模式通过独立服务端进程隔离两份世界
- 脚本只在服务端执行，脚本变量和环境只存在于服务端实体；客户端只接收消息和同步增量
- 读取循环只解析帧并放入同一个请求队列；HELLO、场景修改、锁定和断开等请求由主循环按队列顺序单线程统一处理
- 完整请求到达服务器后按队列生效并广播，不依赖发起客户端继续等待；客户端断开不会撤销已提交的创建或修改

本地状态，不同步：

- 相机视角、背景样式、窗口大小
- 当前选中项和各类管理窗口

说明与限制：

- 拖动时约每 30ms 广播一次物件位置，松开时再发送最终位置
- 单击画布物件、物件管理器行或右键物件时立即申请占用
- 占用中的物件才能拖动；拖动时保持占用，松开不会释放
- 双击已占用的物件进入管理界面；退出管理界面后继续保持选中和占用
- 点击空白处、切换物件、关闭管理器或用户退出时释放占用
- 被占用的物件显示阴影高亮，右下角显示占用者用户名；其他用户点击/拖动会被拒绝，提示中会显示占用者用户名
- 物件管理器中，其他用户占用的行显示灰色遮罩和占用者用户名，当前不可选择
- 用户断开连接时，服务器自动释放该用户占用的所有物件并广播锁状态
- 每个用户最多同时占用一个物件；占用新物件会自动释放旧锁
- 桌面绘制其他在线用户的光标：使用该用户颜色的圆点，右下角为同色小号用户名；物件锁标签和物件管理器中的占用者用户名也使用该颜色；用户颜色默认黑色
- 拖动中的位置会持续同步给其他客户端，其他用户能看到连续移动
- 远端增量只更新对应素材/物件；只有全量快照才会整体替换场景
- 服务器处理删除后，针对该物件的后续更新会被忽略，不会复活
- 如果拖动中的物件被其他客户端删除，本地选择和拖动状态会立即清除
- 名称冲突由服务器生成唯一名称，再同步回客户端
- 同一物件被多个客户端同时修改时仍采用“最后写入获胜”
- 通过 `连接` 菜单启动的新窗口是独立进程，不会影响当前窗口
- 远程连接失败或用户名被拒绝时直接关闭客户端窗口，不回退本地服务
- 用户名在服务器内唯一；冲突时无法加入，客户端直接断开
- 用户名只用于区分客户端，不是密码或鉴权
- 已连接的客户端在服务器断开后直接关闭窗口，同步增量不弹提示
- 服务器发现引用不一致时，会让相关客户端重新获取一次全量快照
- 服务器把场景保存在内存中，重启后清空
- 最多 16 个客户端，TCP 端口默认 7777
- 网络使用 libuv，Linux 和 Windows 共用同一套实现；没有鉴权，建议在可信局域网使用

服务器运行在终端中，按 Ctrl+C 结束。

## 构建运行

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
./image_canvas
```

Windows 在 MSYS2 UCRT64 中执行同样的命令，生成 `image_canvas.exe`。macOS 使用
Homebrew 安装依赖后执行同样的 CMake 命令。GitHub Actions 会构建 Linux、Windows
和 macOS，并运行无头服务端及存档冒烟测试。

服务器运行在终端中，按 Ctrl+C 结束并保存；本地 GUI 关闭时通过已连接的本地会话发送带随机 token 的停止请求，服务端保存后退出。

## 关于 JPEG

raylib 6.2 默认关闭 JPEG（和 TGA）解码，所以 Arch 官方包无法用 `LoadImage` 读取 `.jpg`。
通过 `FetchContent` 或系统包构建 raylib 时，如需 JPEG 支持可显式打开：

```bash
cmake -S raylib-6.2 -B build \
  -DBUILD_SHARED_LIBS=ON -DBUILD_EXAMPLES=OFF \
  -DCUSTOMIZE_BUILD=ON -DSUPPORT_FILEFORMAT_JPG=ON -DSUPPORT_FILEFORMAT_TGA=ON
cmake --build build -j
```

如果改用系统 raylib 且需要 JPEG，也需要这样重新编译。

## 关于字体

字体文件不提交到仓库。CMake 配置时优先在系统字体目录中查找可用的中文 TTF/OTF：
WenQuanYi、Noto Sans CJK 等；找不到时下载 Noto Sans CJK 和 Unifont 到构建目录，
并在构建后复制为：

```text
assets/WenQuanYiMicroHei.ttf
assets/WenQuanYiMicroHeiMono.ttf
assets/unifont.otf
```

界面使用第一项，脚本代码和 `self` 表达式使用第二项，加载失败时回退到 Unifont。
这些生成文件被 `.gitignore` 忽略。

程序启动时按常用 Unicode 范围生成字符集，而不是每次扫描文案；素材名、物件名、
用户名和运行时的中文提示都可以直接显示。

如果新字体加载失败，会回退到 `assets/unifont.otf`。

字体许可：WenQuanYi Micro Hei 系列为 Apache License 2.0；Unifont 为 GPLv2+
（含字体嵌入例外）/ SIL OFL 1.1 双许可；下载的 Noto CJK 为 SIL OFL 1.1。
